# 本地因果广播服务（causal-broadcast-java）

一个单进程、本地持久化的因果广播（causal broadcast）服务。多个参与者通过
HTTP 接口广播与接收消息，服务保证：若消息 `a` 因果先于消息 `b`，则每个接收
方都一定先交付 `a` 再交付 `b`；互相并发的消息，不同接收方的交付顺序允许不同。

## 因果序语义

- 每条广播消息携带一个**向量时钟**作为因果判定元数据，分量键为“参与者 id +
  世代号”（`id#gen`）。
- 发送方广播时在自己的分量上递增；接收方仅当一条消息的全部因果前驱都已交付
  后才交付它，否则先缓冲。
- 同一发送方的消息严格按其分量序号连续交付（不跳号、不提前交付）；不同发送方
  之间只要满足向量时钟前驱关系即可，并发消息交付顺序不作统一规定。
- 参与者**动态加入**：新成员以当前全局时钟为基线，只能参与加入时刻之后的因果
  链；加入之前的消息不会投递给他。
- 参与者**动态离开**：离开前服务会把所有在途消息排干到交付不动点，再移除该成员
  分量。离开的参与者不会阻塞其余人的交付，也不会阻塞元数据回收。
- 同一 id 重新加入会获得**新世代号**，与历史化身的向量分量互不影响。

## 恰好一次交付与去重

- “是否已收到 / 已交付”按 `(消息, 参与者世代)` 持久化；重复调用接收接口是幂等
  的，重复投递不会产生第二次交付。
- 乱序到达的消息先进入缓冲，前驱补齐后按因果序自动释放，不会遗漏。
- 每个参与者世代维护一条独立的、带连续序号的**已交付日志**。

## 稳定元数据回收

- 当一条消息对其全部目标参与者都已交付（全局稳定）后，其向量时钟元数据即可被
  回收（在库中置空），消息正文与已交付日志保留以供拉取。
- 仍在缓冲 / 未送达的消息保留完整向量时钟，因此回收不影响后续因果判定。
- 长时间运行时，保留的因果元数据规模只与“当前在途消息数”相关，不随历史消息总
  数无界增长。

## 持久化与崩溃恢复

- 所有状态（成员、成员时钟、消息及因果元数据、每个参与者的接收/交付状态、交付
  序号）都持久化在本地嵌入式 H2 文件数据库中（JDBC）。
- 每次变更都同步写库；进程崩溃重启后，已交付消息不会重复交付，未交付（含缓冲）
  消息与因果时钟完整恢复，接收前驱后继续按因果序交付。

## HTTP 接口

所有操作在服务端由单把锁串行化，保证交付、回收与拉取游标的并发一致性。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `POST` | `/members/{memberId}` | 加入（或同 id 重新加入）。返回 `memberId`、`generation`、`memberKey`。 |
| `DELETE` | `/members/{memberId}` | 离开；先排干在途消息再移除成员。 |
| `POST` | `/broadcast/{senderId}` | 广播。请求体 `{"payload": "..."}`，返回消息 `id`、`seq`、`clockJson`、`payload`。发送者本人立即交付。 |
| `POST` | `/receive/{receiverId}/{messageId}` | 通知某参与者收到某条广播消息；前驱未齐时缓冲，齐了自动交付。幂等。 |
| `GET` | `/pull/{memberId}?afterSeq=&limit=` | 拉取严格位于游标 `afterSeq` 之后的已交付消息，返回 `messages` 与新游标 `nextSeq`。 |
| `POST` | `/admin/reset` | 清空全部本地状态（测试/管理用）。 |

拉取语义：

- `afterSeq` 省略或为 `0` 表示从头读取；使用上次返回的 `nextSeq` 继续读取。
- 同一游标重复读取得到确定的同一页，不会漏读或重读；游标推进即表示该前缀已被
  消费，后续从 `nextSeq` 读取。
- `limit` 必须在 `1..causal.pull-max-limit` 之间。

典型状态码：`201`（创建/加入/广播）、`200`（成功）、`400`（参数非法）、
`404`（参与者或消息不存在）、`409`（参与者未处于活动状态）。

## 配置项

在 `src/main/resources/application.properties` 中配置：

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `causal.data-dir` | `./data` | 本地 H2 数据库文件目录，重启恢复依赖该目录。 |
| `causal.gc-batch-size` | `100` | 每批回收的稳定消息数；回收会循环执行直到没有候选。 |
| `causal.pull-max-limit` | `500` | 单次拉取允许的最大 `limit`。 |
| `spring.datasource.url` | 指向 `${causal.data-dir}/causal-db` | H2 文件库 JDBC 地址。 |

## 构建与测试

```bash
mvn test      # 编译并运行全部测试
mvn spring-boot:run   # 本地启动，默认端口 8080
```

自动化测试覆盖：乱序到达缓冲、重复消息恰好一次交付、并发因果链、动态加入/离开/
重连、稳定元数据回收、崩溃重启恢复、并发拉取游标一致性以及 HTTP 全流程。
