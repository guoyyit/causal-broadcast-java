# causal-broadcast-java

本地因果广播服务：多个参与者通过该服务交换消息，服务保证每个接收方按因果序交付消息，
状态持久化到本地磁盘并支持崩溃重启恢复。

## 构建与测试

```bash
mvn compile     # 编译
mvn test        # 运行全部自动化测试
mvn spring-boot:run  # 本地启动服务（默认 8080 端口）
```

## 因果序语义

- 每条消息携带发送时的向量时钟作为因果上下文。若消息 `a` 因果先于消息 `b`
  （`b` 的时钟覆盖 `a`），则任何接收方必须先交付 `a` 再交付 `b`；
  并发消息在不同接收方之间可以以不同顺序交付。
- 接收方在消息的全部因果前驱交付之前会缓冲该消息，绝不提前交付；
  前驱补齐后缓冲区自动排空（可能级联交付多条）。
- 重复到达的消息（已交付或已缓冲）会被去重丢弃，不会重复交付。
- 后加入的参与者只从加入时刻起参与因果链：其交付起点初始化为当前各参与者的发送水位，
  不会收到也不会等待加入之前广播的消息。
- 参与者离开后不再接收消息，也不再阻塞其余参与者的交付与元数据回收；
  重新加入时发送序号保持单调递增，交付状态按新加入处理。

## 持久化与崩溃恢复

全部状态（成员、发送序号、交付水位、未交付缓冲区、已交付日志、读取游标、
回收水位）在每次状态变更后原子写入 `{data-dir}/state.json`（临时文件 + 原子移动，
崩溃不会产生半截文件）。进程重启后从该快照恢复：已交付消息不会重复交付，
未交付的缓冲消息与因果元数据完整保留，读取游标不丢失。

## 元数据回收

- 因果判定元数据为向量时钟，大小为 O（参与者数），与消息总数无关。
- 已离开参与者的时钟项在其全部消息被所有活跃参与者交付后达到"稳定"，
  被折叠进持久化的回收水位（`retiredClocks`）并从各参与者时钟中移除；
  去重判定使用回收水位作为下界，回收后因果序判定保持正确。
- 已交付日志随读取游标推进而裁剪（可配置保留游标之后的若干条）。
- 回收在交付、离开、拉取时自动触发，也可通过 `POST /api/admin/gc` 手动触发。

## HTTP 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/participants/{id}/join` | 加入（或离开后重新加入），幂等 |
| DELETE | `/api/participants/{id}` | 离开广播组 |
| GET | `/api/participants` | 列出全部参与者状态 |
| GET | `/api/participants/{id}` | 查询单个参与者状态 |
| POST | `/api/messages/broadcast` | 广播消息，请求体 `{"senderId":"...","payload":"..."}`，返回带向量时钟的消息信封 |
| POST | `/api/messages/receive/{receiverId}` | 向指定接收方注入消息信封（模拟网络到达，可乱序/重复），返回 `DELIVERED/BUFFERED/DUPLICATE/REJECTED` |
| POST | `/api/participants/{id}/pull?limit=N` | 按接收方拉取已交付消息并原子推进读取游标，返回 `{cursor, messages}` |
| POST | `/api/admin/gc` | 手动触发元数据回收 |

错误码：未知参与者返回 404，对已离开参与者执行广播/接收返回 409。

典型流程：`join` → `broadcast` 得到消息信封 → 信封经 `receive` 到达各接收方
（开启 `auto-fanout` 时由服务自动扇出）→ 接收方客户端用 `pull` 按游标拉取已交付消息。
并发 `pull` 被串行化，不会漏读或重复读取，游标推进与持久化状态一致。

## 配置项

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| `causal.broadcast.data-dir` | `./data` | 状态快照存放目录 |
| `causal.broadcast.auto-fanout` | `true` | 广播是否自动扇出到所有活跃参与者；关闭后需通过 receive 接口显式投递 |
| `causal.broadcast.delivered-retention` | `0` | 读取游标之后保留的已交付消息条数 |
